# SmartDemand-AI

SmartDemand-AI is a machine learning application that predicts hourly bike rental demand based on temporal, weather, and contextual factors.

The project combines an XGBoost regression model with a Streamlit web application and an LLM-powered explanation layer using the OpenRouter API.

### Live Demo

[SmartDemand-AI – Live Demo](http://16.61.56.50:8501)

## Business Problem

Bike-sharing services need to anticipate rental demand in order to allocate bicycles efficiently and reduce shortages or unused capacity.

The goal of this project is to predict the number of bike rentals for a given hour using historical rental data, time-related features, weather conditions, and contextual information.

## Dataset

The dataset used in this project is the Kaggle Bike Sharing Demand dataset.

It contains hourly bike rental records together with temporal, weather, and contextual variables. The main target variable is `count`, which represents the total number of bike rentals for a given hour.

The dataset contains 10,886 records and 12 original variables.

### Main Variables

| Variable | Description |
|---|---|
| datetime | Date and time of the rental record |
| season | Season of the year |
| holiday | Whether the day is a holiday |
| workingday | Whether the day is a working day |
| weather | Weather conditions |
| temp | Temperature |
| atemp | Feels-like temperature |
| humidity | Humidity level |
| windspeed | Wind speed |
| count | Total number of bike rentals (target) |

## Machine Learning Workflow

The machine learning workflow followed these main steps:

1. Data exploration and analysis.
2. Analysis of categorical variables using bar plots.
3. Analysis of numerical variables and their relationship with bike rental demand.
4. Correlation analysis between numerical features.
5. Feature engineering from the `datetime` variable:
   - year
   - month
   - day
   - hour
6. Removal of the original `datetime` column.
7. Removal of `casual` and `registered` to prevent target leakage.
8. Train-test split using an 80/20 ratio.
9. Model training using Scikit-learn Pipelines.
10. Model evaluation and comparison.
11. Selection and saving of the best-performing model.

## Model Comparison

Four regression models were trained and evaluated:

| Model | MSE | MAE | R² Score |
|---|---:|---:|---:|
| Linear Regression | 19,945.37 | 105.34 | 0.396 |
| Random Forest | 1,805.69 | 27.16 | 0.945 |
| Decision Tree | 3,691.50 | 37.11 | 0.888 |
| XGBoost | 1,590.45 | 26.41 | 0.952 |

## Why XGBoost?

XGBoost achieved the best overall performance among the evaluated models.

It obtained the highest R² score and the lowest MSE and MAE, making it the selected model for the final application.

### Final Model Performance

- **R² Score:** 0.952
- **MAE:** 26.41 bike rentals
- **MSE:** 1,590.45

These results indicate that the model can explain approximately 95% of the variance in hourly bike rental demand on the test data.

## AI Explanation with OpenRouter

SmartDemand-AI combines machine learning with an LLM-powered explanation layer.

The XGBoost model generates the hourly bike rental demand prediction, while an LLM accessed through the OpenRouter API generates a simple explanation based on the selected input conditions and the predicted demand.

This provides users with additional context instead of displaying only a numerical prediction.

For example:

> Demand is expected to be high due to favorable weather conditions and the selected time and day. Additional bicycles may be needed to reduce potential shortages.

The LLM is used only to explain the prediction. The actual demand prediction is generated by the trained XGBoost machine learning model.

## Docker

The application is containerized using Docker, allowing it to run consistently across different environments.

The Docker container installs all required dependencies, including the libraries required to load and run the trained XGBoost model.

The OpenRouter API key is provided through an environment variable and is not stored inside the Docker image or repository.

### Build and running the Docker Image

```bash
docker build -t smartdemand-ai .

docker run -p 8501:8501 --env-file .env smartdemand-ai
```

## AWS Deployment

SmartDemand-AI is deployed on an AWS EC2 instance using Docker.

The application runs inside a Docker container and is exposed through port 8501, making the Streamlit application accessible through a public URL.

### Deployment Architecture

User → AWS EC2 → Docker Container → Streamlit → XGBoost + OpenRouter API

The OpenRouter API key is provided through an environment variable and is not stored in the GitHub repository or Docker image.
